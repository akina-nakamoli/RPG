# 在线账号与云存档部署

本次提供配置模板，不代表已经部署到公网。需要你提供服务器、域名与数据库访问权限。

## 部署结构

Unity → HTTPS/Caddy:443 → 127.0.0.1:5080 Node.js → MongoDB。
使用独立的数据库用户，只授予 `rpg_game` 所需读写权限。生产连接字符串仅放服务器环境文件。

1. 准备 Linux 服务器，安装 Node.js 20+、Caddy，并配置域名 A/AAAA 记录。
2. 创建专用系统用户 `rpg-api`，将 Server 内容放 `/opt/rpg-api`，执行 `npm ci --ignore-scripts`。
3. 按 `server.env.example` 创建 `/etc/rpg-api.env`，替换真实凭据，设置所有者 root、权限 600。
4. 安装 `rpg-api.service` 到 `/etc/systemd/system/`，确认 Node 路径，启动并启用服务。
5. 将 Caddyfile 的示例域名换成你的真实域名，安装到 `/etc/caddy/Caddyfile`，验证配置后重载。
6. 防火墙仅开放 HTTPS 所需的 80/443；SSH 限制来源。5080 和 27017 不对公网开放。
7. Unity `Assets/Resources/DatabaseConfig.json` 的 apiUrl 改成 `https://你的域名/api`。不关闭证书验证。

Caddy 的域名 HTTPS 与证书管理遵循 [官方说明](https://caddyserver.com/docs/quick-starts/https)。
公网必须用 HTTPS；本机开发仍允许 HTTP。不自动购买服务器、修改 DNS 或开放端口。

## 存档与断网

登录必须在线验证身份。成功登录后加载三个槽位，不缓存明文密码或登录令牌到磁盘。
保存先写本地，云上传异步执行，每 15 秒尝试同步待上传进度。网络失败不会丢掉本地存档。
云端每槽使用版本号和请求 ID：旧版本不能覆盖新版本，相同请求重试不重复写入。
发生冲突后，回到登录存档界面选择 KEEP LOCAL 或 USE CLOUD；未选择前禁止进入该槽。
保留被替换的一方到本地 conflict-backup 文件。KEEP LOCAL 仍受版本检查，其他设备再次写入会再次提示冲突。
首次启动断网不能登录；退出时不等待云上传完成，待上传本地进度下次在线登录后继续同步。

## 认证与运维

密码保持加盐 scrypt；令牌仅在 MongoDB 存哈希，24 小时到期，可注销撤销，后端重启不会清空有效会话。
到期后要求重新登录，不无限延长会话。sessions 的 TTL 仅做清理，请求本身也检查过期时间。
同账号认证限流、请求来源限流、认证并发限制、1MB 请求上限。单机内存限流不适合直接扩展成多实例。
检查 health 接口、systemd/Caddy 错误日志，日志不要记录请求正文、密码或令牌。
设置数据库每日备份和保留周期，定期实际验证恢复；单槽 previousData 不能替代数据库备份。

## 仍需上线前完成

- 邮箱验证、忘记密码：需选定邮件服务和账号恢复策略，目前未添加不安全的无身份验证重置接口。
- 公网证书、真实 DNS、云数据库备份、监控报警：必须在真实服务器上部署并验证。
- 多实例部署需共享限流服务；竞争存档只保证数据不覆盖，不构成反作弊。
- 不信任客户端金币/经验：若加入排行榜或交易，应由服务器执行玩法规则。
- 打包后的 Unity 测试慢网、超时、注销、冲突选择、断网退出、重启恢复以及两台设备竞争保存。
